# Slotted Aloha 시뮬레이터 — 새 세션용 개발 프롬프트

아래 내용을 기준으로 기존 프로젝트의 다음 개발 단계를 이어서 진행해 줘. 먼저 실제 소스와 설계 문서를 읽고 구현 상태를 확인해 줘. 이 문서 이후의 사용자 지시가 있으면 그 지시를 우선해 줘.

정리 기준일은 **2026-11-17**, 현재 프로그램 버전은 **1.5.0.0**이다. 1.5.0.0에서 **단말 수 비례 슬롯 배정**(그룹 설정 창 버튼, ``SlotMode`` 균등·비례·직접)을 추가했다. 1.4.0.0에서 **반복 실행 평균**(반복 횟수 입력, 평균·표준편차·최소·최대, Excel ``반복 실행`` 시트)을 추가했다. 1.2.0.0에서 **그룹별 슬롯 배정**과 **같은 시드의 그룹 미적용 비교**를 구현했다. 1.3.0.0에서 그룹 설정 창(채널 타입·설정 결과 표·사용 방법·전체 배정 해제), 특정 그룹 단말 수만 바꾸는 자동 맞춤, 결과 화면(설정 값 카드·그룹 합계 행·표 높이 조절·표 전환 깨짐 수정), 주파수 1을 맨 아래로 그리는 격자, Excel 계열 이름과 합계 행을 반영했다. 다음 개발 과제는 아직 정하지 않았다.

## 2. 먼저 읽을 파일과 코딩 규칙

`doc/README.md`는 실행·빌드 안내, `doc/DESIGN.md`는 설계(그룹 기능 포함)다. 코드 수정 전에 `doc/CODING_RULES.md`를 읽는다.

- 함수명·변수의 의미 이름·사용자 정의 타입은 PascalCase. 함수명의 첫 단어는 동사.
- 함수 선언과 정의의 반환형·함수명·매개변수 목록은 한 줄에 작성.
- `typedef struct` 타입 이름은 `_t`로 끝냄.
- 가능한 경우 `int`·`unsigned int`·`BOOL` 대신 `<stdint.h>`의 고정 폭 정수 사용. 표준이 정한 진입점 시그니처는 예외.
- 변수 접두어 순서는 `g`, `p`, `a`, `u`, 기본 타입 접두어. 예: `uiCount`, `ullRound`, `pResult`, `auiSlots`, `aauiGroupSucceeded`.
- 구조체 값은 `Result`, 구조체 포인터는 `pResult`처럼 작성.
- 제어문의 여는 중괄호는 같은 줄, `else`는 닫는 중괄호 다음 줄. `case`와 `default`는 `switch`와 같은 들여쓰기.
- 상수를 왼쪽에 쓰는 비교는 `==`, `!=`에만 적용.
- 크기를 제한하는 출력 함수를 사용하고 `snprintf`, `swprintf` 등의 반환값으로 오류·잘림을 검사.
- 의미 있는 예외 처리는 작성하되 의미 없는 빈 `else`를 추가하지 않음.

## 3. 시뮬레이션 규칙 (구현 완료)

Alert와 LB는 서로 독립된 경쟁 영역이다. 단말 수 N은 실제 단말 수이며, 활성 영역마다 같은 N대가 참여한다.

입력 파라미터는 9개다: 심볼레이트(500/2000/4000 sps), Wave ID(3/13), Alert 채널 수, LB 채널 수, 단말 수, 슈퍼프레임 주기(초), 시뮬레이션 시간(초), **그룹 수(0~100, 0 = 미적용)**, **반복 횟수(1~10,000)**. 시뮬레이션 탭 입력은 5열 2줄이다.

시간은 소수 셋째 자리까지 입력하며 내부에서 밀리초 정수로 처리한다. 채널 수는 그 영역 전체의 실제 슬롯 칸 수다. 시간 슬롯 수는 500/2000/4000 sps에서 Wave ID 3이면 9/36/72, Wave ID 13이면 3/12/24이다. 주파수 방향 크기는 `ceil(영역 채널 수 / 시간 슬롯 수)`다.

- 모든 단말은 같은 슈퍼프레임 주기에 각 활성 영역에서 한 번씩 전송을 시도한다. 첫 수신 집계 시점은 한 주기가 지난 시점이다.
- 한 칸에 시도 0건은 유휴, 1건은 성공, 2건 이상은 충돌이다. 성공한 단말도 다음 주기에 다시 경쟁한다.
- 채널 수가 0인 영역은 경쟁하지 않으며 그룹 검사에서도 제외한다. 단말 0대와 완료 회차 0회도 처리한다.
- 회차 이동은 시드로 해당 회차를 다시 계산해 격자를 만들고, 누적 값은 저장된 회차별 집계를 합산한다.

## 4. 그룹별 슬롯 배정 (1.2.0.0 구현, 1.3.0.0 개선)

사용자 표현의 ‘영역’ = ‘그룹’이다. 화면·파일은 기존 ‘영역’(Alert·LB)과 구분하기 위해 ‘그룹’으로 표시한다.

- 그룹 수는 Alert와 LB가 공유한다. 그룹별 단말 수는 영역마다 따로 정할 수 있다.
- 단말은 그룹 순서대로 단말 수만큼 연속 ID로 배정한다. 단말 수 0인 그룹에는 아무도 접속하지 않는다.
- 같은 영역의 한 칸은 한 그룹에만 배정한다. 미배정 칸은 항상 유휴다.
- 기본값은 단말 균등 분배·슬롯 균등 배정(슬롯 번호 순서의 연속 블록)이다. 자동인 값은 파라미터 변경에 따라 자동으로 다시 배분한다.
- 단말 수는 그룹마다 직접(고정)/자동이다. 한 그룹을 바꾸면 그 그룹만 고정되고 자동 그룹이 `N − 고정 합계`를 균등하게 나눈다(나머지는 앞 자동 그룹부터). 빈 값으로 변경하면 자동으로 돌아간다. 모두 자동이면 기존 균등 분배와 같다.
- 직접 지정한 값은 자동으로 고치지 않는다. 다음 경우 실행 전에 오류로 알린다.
  - 단말 합계 불일치
  - 칸 없는 그룹
  - 범위를 벗어난 칸
  - 없어진 그룹의 칸

  범위를 벗어난 칸은 사용자가 그룹 설정 창에서 해제를 확인해야 지운다.
- 그룹 1개·전체 칸이면 고정 시드 결과가 그룹 미적용과 같다. 단말 순서와 `SelectSlot` 호출 순서를 바꾸지 않는다. LB는 Alert가 소비한 난수 상태를 이어받는다.
- 그룹을 쓴 실행은 같은 시드로 그룹 미적용 결과도 함께 계산해 비교한다.

화면:

- **시뮬레이션 탭:** `그룹 설정` 버튼, Alert·LB 두 줄 요약(오류 시 빨간색), 상태 줄의 첫 오류, 그룹 색 미리보기.
- **그룹 설정 창:**
  - 채널 타입(Alert/LB) 선택, 사용 방법 버튼, 그룹 설정 결과 표(채널 타입별 단말 합계·단말 배정·배정 칸·미배정·슬롯 배정·검사)
  - ① 그룹 표(그룹·단말 수·지정·단말 ID·배정 칸 수), ② 단말 수 변경·단말 균등 분배, ③ 슬롯 균등 배정·단말 수 비례 배정·전체 배정 해제
  - 격자 클릭·드래그 편집. 선택 그룹 칸에서 시작하면 해제하고, 다른 그룹 칸은 건너뛴다.
  - 시간·주파수 범위 입력, 범위 밖 배정 해제, 적용·취소
- **결과 탭(그룹 실행):**
  - 그룹 선택(채널 타입 전체/그룹 n/그룹별 비교)과 그룹 배정 보기 전환
  - 그룹 전송 추이와 그룹별 작은 그래프
  - 하단 표 전환(채널 타입 통계/그룹 통계/미적용 비교). 그룹 통계는 채널 타입마다 굵은 `합계` 행(그룹들의 합, 미배정 제외)이 있다.
  - 회차 이동 줄과 표 사이 구분선을 끌어 그룹 통계 표 높이를 조절한다. 표 전환 후 결과 페이지 전체를 다시 그린다.
  - 설정 값은 카드로 표시한다(공통 설정 3열 + 채널 타입별 채널 수·주파수 위치·단말 배정·슬롯 배정 표).
  - 최종 접속 실패 단말 갯수 표: `채널 타입 | 그룹 적용 | 그룹 미적용`(그룹 미사용 실행은 `채널 타입 | 단말 갯수`).

화면과 Excel의 표 머리글과 안내 문구는 Alert·LB를 "채널 타입"으로 부른다(문서의 "영역"과 같은 뜻). 그룹을 쓰지 않은 실행도 설정 값 카드를 쓰며 그룹 수는 "0 (미적용)"으로 표시한다. 최종 결과 표기는 화면·파일 모두 **최종 접속 실패 단말 갯수**다.

## 4-1. 반복 실행 평균 (1.4.0.0)

- 반복 1 = 기존 시드의 상세 실행(화면·회차 표·Excel 회차 시트). 반복 k ≥ 2는 `GetRepeatSeed(시드, k)`로 처음부터 다시 계산해 최종 값만 `RepeatSample_t`에 보관한다. 같은 시드의 전체 실행과 정확히 같다.
- 반복 후 반복 1의 마지막 회차를 다시 계산해 격자를 복원한다. 중지하면 결과를 버린다.
- 통계: 평균, 표본 표준편차(n−1), 최소, 최대. 차이는 반복마다 적용 − 미적용.
- 화면: 설정 값 카드 반복 횟수, 접속 실패 표 `평균 ± 표준편차`, 하단 표 `반복 통계`(기본 선택). Excel: 마지막 시트 `반복 실행`.
- 검증 결과: 2,000회 평균이 닫힌식과 일치(그룹 적용 61.75 vs 61.66, 미적용 60.77 vs 60.86). 이 모델에서 칸당 단말 수가 같으면 그룹을 나눠도 평균 실패 수는 줄지 않는다. 사용자 질문으로 원인을 설명했고, `build/verify/Analyze.c`가 그 분석 프로그램이다. 단말 수 비례 슬롯 배정은 1.5.0.0에서 구현했다(그룹 1 = 50대 예: 균등 72.1대 → 비례 61.5대).

## 5. 결과 화면과 Excel 규칙 (유지)

- 최상위 탭은 정확히 **시뮬레이션**, **결과**. Alert가 위, LB가 아래. 주파수 축 직선은 이름 열과 칸 영역 사이. 축 제목은 **주파수**, **시간**. 각 영역의 맨 아래 줄이 주파수 1(가장 낮은 주파수)이고 축 옆에 주파수 번호를 표시한다.
- ‘전체’ 집계는 화면과 파일에서 삭제한 상태다. `uiUnsuccessfulAnywhere`가 남아 있어도 복구하지 않는다.
- 전송 추이의 각 표시 지점에 숫자를 붙이고, 회차가 많으면 선택 회차에 맞춘 연속 구간을 표시한다.
- `결과 파일 생성`은 XLSX 한 파일을 저장한다. 성공 시 **`[파일 이름] 파일 생성 완료`** 알림창을 띄운다. 임시 파일에 완성한 뒤 교체한다.
- 그룹 미사용 실행: `결과`, `회차별 데이터` 두 시트. 1.3.0.0부터 이름 변경과 계열 이름 참조 때문에 XML은 1.1.0.0과 다르다.
- 그룹 사용 실행: `결과`(+그룹 수, 적용·미적용·차이 비교표, 비교 차트 4개), `그룹 설정`(단말 수 지정 직접/자동 열 포함), `그룹별 결과`(영역별 `합계` 행), `미적용 비교`, `회차별 데이터`, `그룹별 회차 데이터`(그룹 단위로 행 제한에 맞춰 `… 2`, `… 3` 시트로 분할).
- 차트 계열 이름은 `결과` 시트의 숨긴 Z4:Z9 셀을 `strRef`로 참조한다(Excel 외 프로그램에서 '계열 1'로 보이지 않게).
- 저장 한도:
  - 최대 1,048,573회차
  - 압축하지 않은 ZIP이라 4GB 미만. `CheckExportLimits`가 저장 전에 예상 크기를 검사한다.
  - 15자리를 초과하는 정수는 텍스트로 저장한다.

## 6. 빌드와 검증

프로젝트 루트의 PowerShell에서 `.\Build.ps1`을 실행한다. 링크 옵션 `-Wl,--no-insert-timestamp`로 PE 헤더의 빌드 시각을 0으로 고정해, 같은 GCC(현재 MinGW-Builds 15.2.0 x86_64-posix-seh)에서는 빌드 결과가 바이트 단위로 같다(2026-11-19 GitHub에서 새로 받은 폴더와 로컬 빌드의 SHA-256 일치 확인). 출력은 `build/SlottedAlohaSimulation.exe`와 `excute`의 두 ZIP이다. 빌드된 EXE가 실행 중이면 종료 후 재빌드한다. 소스 ZIP은 `src`, `doc`, `Build.ps1`만 포함한다.

1.2.0.0과 1.3.0.0에서 `build/verify`의 임시 프로그램(`Run.ps1 -Report`, `CheckXlsx.ps1`)으로 다음을 확인했다(영구 자동 테스트 스위트로 가정하지 않는다).

- 그룹 미사용·그룹 1개 전체 칸 결과가 원본 1.1.0.0 코어와 회차별로 일치
- 그룹 간 충돌 없음, 같은 그룹 2대 1칸은 매 회차 충돌
- 그룹·영역 합계와 유휴 칸 관계식, 모든 회차의 누적 값 일치
- 검사 오류 검출(단말 합계, 칸 없는 그룹, 범위 밖 칸, 없어진 그룹의 칸)
- 단말 0대, 0회차, 비활성 영역
- 한 그룹 고정 시 자동 그룹이 나머지를 나눔, 고정 합계 초과·부족 오류, 전체 배정 해제 후 칸 없는 그룹 오류
- 그룹 XLSX의 모든 차트 지점과 참조 셀 일치, 계열 이름 참조, 그룹별 결과 합계 행, 대용량 실행의 시트 분할과 차트 참조(1.2.0.0)
- Win32 메시지로 EXE를 조작해 시뮬레이션 탭·그룹 설정 창·결과 탭 화면 캡처 확인

검증 파일은 `build` 또는 임시 폴더에서 관리하고 소스 ZIP에 넣지 않는다. 이 PC에는 Excel이 설치되어 있지 않아, Excel에서 실제로 여는 확인은 사용자가 해야 한다.
